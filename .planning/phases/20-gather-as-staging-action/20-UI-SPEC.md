## State Contract — 5 States

The Gather button has **5 distinct states**, not 3 as initially proposed (D-03 evolved to D-13). Each state is triggered by a specific scene condition and transitions via click or filter change.

### State Hierarchy

```
┌─ Disabled (no filter OR zero match)
├─ Armed (filter active, set ≥1, no sphere)
├─ Staged—Current (sphere exists, matches filter exactly)
├─ Staged—Drifted (sphere exists, filter changed since gathering)
└─ Stranded (filter is empty, sphere still exists)
```

### State Definitions & Transitions

| State | Condition | Click behavior | Hover behavior | Cursor | Label | Copy basis |
|-------|-----------|-----------------|------------------|--------|--------|-----------|
| **Disabled — no filter** | `!filterState.isActive()` | No-op (pointer-events: none) | No visual change | `not-allowed` | `GATHER` (ghosted, teal 0.35 opacity) | Button dormant; filter is empty |
| **Disabled — zero match** | `filterState.isActive() && matchedCount === 0` | No-op (pointer-events: none) | No visual change | `not-allowed` | `0 CASES — REFINE` | Filter is active but set is empty; prompt user to refine |
| **Armed** | `filterState.isActive() && matchedCount >= 1 && !sphereExists` | Call `gather(objects)` → sphere created | ~150ms ease-out, border glow, full opacity → 1.0 | `pointer` | `GATHER` | Ready to stage; click stages current filter |
| **Staged—Current** | `sphereExists && matchedCount === sphereCount` | No-op (button is inert; cursor: default signals no action available) | No visual change (button is steady-state) | `default` | `GATHERED · N` (where N = matched count) | Sphere reflects current filter; no new gather needed |
| **Staged—Drifted** | `sphereExists && matchedCount !== sphereCount` | Call `gather(objects)` → sphere replaced | ~150ms ease-out, border glow (opacity 0.7) | `pointer` | `RE-GATHER · N→M` (N = current staged, M = new matched) | Filter changed; click re-gathers with new filter |
| **Stranded** | `!filterState.isActive() && sphereExists` | Call `disposeStagingNucleus(objects)` → sphere deleted | ~150ms ease-out, border glow | `pointer` | `DISMISS` | Filter was cleared; sphere orphaned; dismiss it |

### State Transitions (Decision Tree)

```
User action / filter change → State determination:

1. applyFilter() mutates filterState
2. (No scene effect; filter is silent per D-04)
3. At next button-state-check (in listener or recompute):
   IF filterState.isActive() && matchedCount >= 1 && !sphereExists
     → Armed
   ELSE IF !filterState.isActive() && sphereExists
     → Stranded
   ELSE IF filterState.isActive() && matchedCount >= 1 && sphereExists
     → IF matchedCount === sphereCount → Staged-Current
        ELSE → Staged-Drifted
   ELSE
     → Disabled

Button click triggers action:
   Armed → call gather() → sphere created → recompute → Staged-Current
   Staged-Drifted → call gather() → sphere replaced → recompute → Staged-Current (if filter still matches)
   Stranded → call disposeStagingNucleus() → sphere removed → recompute → Disabled
```

## Interaction Contract

### Click Behavior

| From state | Click → Action | Result |
|-----------|----------------|--------|
| Armed | `gather(objects)` | Calls the new entry point in `src/scene/staging.ts`. Composes existing lifecycle: `createStagingNucleus` + `applyStagingPush` + `zoomTowardStaging`. Sphere appears in scene. Button transitions to Staged-Current. |
| Staged-Current | No-op | Button is inert (cursor: default). Click produces no effect. State changes only when filter mutates (→ Staged-Drifted) or is cleared (→ Stranded). |
| Staged-Drifted | `gather(objects)` | Calls `gather()` again. The sphere is replaced (not updated in-place). New set of stars travel to the new sphere. Button transitions back to Staged-Current. |
| Stranded | `disposeStagingNucleus(objects)` | Calls the existing disposal entry point. Sphere is deleted. Ghost stars (if any) are shown briefly then dissolve. Button transitions to Disabled. |
| Disabled | No-op | No response; pointer-events: none. |

### Hover Behavior

| State | Hover Effect | Duration | Easing |
|-------|------------|----------|--------|
| Armed | Border color → `--gold`, opacity → 1.0; text opacity → 1.0 | ~150ms | `ease-out` (not the project ease; standard ease-out for micro-interaction) |
| Staged-Current | No hover effect (inert) | — | — |
| Staged-Drifted | Border color → `--gold`, opacity → 0.7 → 0.75 (slight brightening to signal availability) | ~150ms | `ease-out` |
| Stranded | Border color → `--teal`, opacity → 0.5 → 0.6 | ~150ms | `ease-out` |
| Disabled | No hover effect | — | — |

**Note**: Hover uses a standard `ease-out` (micro-interaction timing ~150ms), not the project ease (which is reserved for transitions T1–T6). This matches the existing `.sl.hover` pattern (stars' label hover).

### Focus (Keyboard)

| Aspect | Behavior |
|--------|----------|
| Focus ring | Standard browser outline (blue ring), 2px width, 2px offset. When `:focus-visible` is set, show ring. When `:focus:not(:focus-visible)` (mouse click), hide ring. |
| Tab order | Button is inside the unified left column, below the accordion. Tab order follows the accordion's last focusable element → Gather button → column edge. |
| Enter key | When button has focus and is Armed/Staged-Drifted/Stranded, Enter triggers the click action (same as mouse click). |
| Space key | Same as Enter. |

### Keyboard Accessibility (Semantics)

- Button element: `<button class="gather-button" aria-label="{dynamicLabel}" aria-pressed="{true/false}">GATHER</button>`
- `aria-label` updates with state:
  - Armed: `"Gather N cases to staging area"`
  - Staged-Current: `"Gathered: N cases currently staged"`
  - Staged-Drifted: `"Filter changed. Re-gather with new set: N to M cases"`
  - Stranded: `"Dismiss orphaned staging sphere"`
  - Disabled: `"Cannot gather: no filters active or empty result set"`
- `aria-pressed="true"` when Staged-* states (button is "pressed in" semantic, holding the sphere). `false` otherwise.

### Reduced-Motion Behavior

| Element | Standard | Reduced-motion |
|---------|----------|-----------------|
| Border hover glow (~150ms) | Ease-out over 150ms | Instant swap; no transition |
| Filter-to-state recompute | Real-time as filter changes | Real-time (no animation, so unchanged) |
| All GSAP-driven scene animations called by gather() | Per-phase T-values (T2, T5, etc.) | Per `prefers-reduced-motion` gate in existing `gather()` lifecycle (unchanged from previous phases) |

**Button itself**: The button label changes (e.g., "GATHER" → "RE-GATHER · 5→8") instantly when state shifts. This is not an animation; it's a text update. No gate needed.

## View-State Gating (D-10)

**Gather button is present only in `global` + `constellation` views.**

| View state | Button DOM | Visibility | Interaction |
|-----------|-----------|-----------|--------------|
| `global` | Present in DOM | Visible | Fully interactive |
| `constellation` | Present in DOM | Visible | Fully interactive |
| `planetary` | Absent from DOM | N/A (display: none, or not rendered) | N/A |
| `reading` | Absent from DOM | N/A (display: none, or not rendered) | N/A |

**Implementation pattern**: Two options; planner chooses (ui-checker flagged this as a planner-owned implementation decision, not a spec defect):
- **Option A — CSS body-class gating** (preferred if consistent with Phase 17/18 patterns): Add a `body.reading` class toggle alongside the existing `body.planetary`/`body.constellation`/`body.global` toggles in the view-state machine, then `body.planetary .gather-button, body.reading .gather-button { display: none !important }`. Note: `body.reading` does NOT currently exist in `src/style.css` — only `body.planetary` and `body.constellation` do. If choosing Option A, adding the `body.reading` class toggle is part of Phase 20 scope.
- **Option B — JS conditional render**: `filter-panel.ts` renders or removes the button from DOM based on `objects.mode` (or the view-state machine). No new body-class needed.

Either path satisfies D-10. Planner picks based on existing pattern consistency.

**Rationale**: planetary is the overture (no filter panel visible); reading is the instrument-readout surface (no gathering from within a case read). Gathering happens at the discovery/inquiry stage (global/constellation).
