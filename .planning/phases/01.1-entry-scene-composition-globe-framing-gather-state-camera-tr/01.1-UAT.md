## Notes

### Phase 01.1 Scope vs. v3.4 Future Work

The Entry overlay in this build is the **mountEntryScreen overlay** that fires after the first user gesture (click/Enter/Space) cancels the calibration overture. This is the "skippable" pattern from Phase 16-03 (v3.3): overture plays autonomously, first gesture commits to Entry. This is NOT a regression — it's the expected v3.4 onboarding flow as documented in CONTEXT.md D-04.

**Out-of-scope finding (not a Phase 01.1 gap):** Before the first click, the ambient calibration overture stays running indefinitely (`__overtureComplete` returned false at 10s+ wait). This is the Phase 16-03 calibration sequence behavior; it's separate from Phase 01.1's Entry composition deliverable. If the calibration overture should auto-complete (rather than waiting for user gesture), that's a Phase 16-04 or new-phase concern, not a Phase 01.1 issue. Surfacing for visibility.

### Tooling notes carried forward (for future phases)

1. **`gsd-sdk phase-plan-index` wave grouping disagrees with frontmatter** — phase-plan-index reported plan 05 in Wave 1 alongside implementation plans; plan frontmatter correctly declares Wave 3 with `depends_on: [01,02,03,04]`. Followed frontmatter (the contract). Worth a memory entry.

2. **`Agent(isolation: "worktree")` creates worktree from stale base** — first attempt at Wave 0 spawned a worktree from commit `136ed5f` (pre-TypeScript v2) instead of `draft` HEAD. Fell back to `workflow.use_worktrees: false` for the rest of execution. Root cause not investigated. Memory entry needed before re-enabling worktrees.

3. **Two Playwright MCP servers wired** — `mcp__playwright__*` (Windows Chrome via CDP attach, project-specific wrapper) is the correct tool. `mcp__plugin_playwright_playwright__*` (plugin-bundled, launches WSL Chromium) is the broken path. Always check `navigator.userAgent` shows `Windows NT` before running UAT.

4. **WebGL canvas pixel readback returns blank** — `preserveDrawingBuffer` is false on the renderer, so `tmpCtx.drawImage(canvas, 0, 0)` followed by `getImageData` returns 0 in every channel. Use `browser_take_screenshot` (OS-level capture) for visual verification, not pixel sampling.
