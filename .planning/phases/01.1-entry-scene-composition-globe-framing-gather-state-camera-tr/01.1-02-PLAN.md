  <action>
The renderer module does not have access to the `entryFramingActive` flag from main.ts directly. There are two clean patterns:

**Pattern A (recommended for simplicity):** Pass a getter function during renderer creation, or attach the flag to the camera object as userData.

**Pattern B:** The ResizeObserver re-applies applyEntryFraming unconditionally if the camera has a view offset already set (read `camera.view.enabled`).

Implement Pattern B (least invasive, aligns with D-01.1-06 "claude's discretion"):

Modify the `onContainerResize` function inside `createRenderer`:

```typescript
const onContainerResize = () => {
  const w = container.clientWidth;
  const h = container.clientHeight;
  
  // Re-apply Entry framing if camera has view offset active
  // (from Entry state). During normal State 1/2, camera.view.enabled is false.
  if (camera.view?.enabled) {
    // Import applyEntryFraming at top of file
    applyEntryFraming(camera, w, h);
  }
  
  camera.aspect = w / h;
  camera.updateProjectionMatrix();
  renderer.setSize(w, h, false);
};
```

Add import at the top of renderer.ts:
```typescript
import { applyEntryFraming } from './entry-framing';
```

Rationale: during Entry, camera.view is active (applyEntryFraming was called). During State 1/2, camera.view.enabled is false (clearEntryFraming is called in the choreographer). So the ResizeObserver reads the camera state directly instead of needing a separate flag.
