## Decisions Made

- **`clearEntryFraming(camera)` in `onComplete`, not `camera.clearViewOffset()` directly.** The Wave 0 contract establishes `entry-framing.ts` as the single projection-manipulation surface; calling `clearViewOffset` directly would bypass that abstraction. The wrapper is a one-line pass-through so there's no behavioral difference — but the import surface stays coherent across waves.

- **Unused `clearEntryFraming` import removed from test file.** The test file's `clearEntryFraming` import was added for RED-phase intent (to spy on it) but the spy target is actually `camera.clearViewOffset`, which is the concrete method the implementation calls. Under `noUnusedLocals: true`, the import causes a build failure. Removed; the test still correctly verifies the behavior via the `clearViewOffset` spy.

- **`vi.mocked(gsap.to).mock.calls.find()` pattern for proxy tween detection.** The existing mock has a global `capturedOnComplete` that gets overwritten by each `gsap.to` call — using it to identify the proxy tween's `onComplete` would be fragile (4 `gsap.to` calls in the function). The `find(([target]) => 'dx' in target)` approach cleanly identifies the specific call without depending on call order.
