<decisions>
## Implementation Decisions

### Camera framing mechanism (locked)
- **D-01.1-01:** Use a **camera target offset** during Entry, not a position move. The planet origin stays at (0,0,0). The camera position stays at the State 1 position `(80, 880, 280)`. Only the camera's `lookAt` target is shifted off-center — leftward in screen space — so the planet renders in the right half of the viewport. This is the lower-mechanical-risk path: the choreographer's existing `flyTo(targetPos, targetLookAt, duration)` API handles target tweens natively, and we don't fork the camera state machine.
  - **Why not move the camera position?** Position moves change perspective (planet apparent size, scene depth). The handoff Entry has the planet at a specific apparent radius; matching that with a position move requires recomputing FOV/distance. Target offset preserves the existing camera intrinsics and produces the same "planet on the right" composition by re-aiming.

### Entry camera offset values (locked)
- **D-01.1-02:** Concrete target offset on Entry: `lookAt = (offsetX, 0, 0)` where `offsetX` is computed to put origin (0,0,0) at NDC (0.44, -0.16) per the handoff's cx:72% / cy:58% framing (NDC = 2 × normalized − 1 → x: 0.44, y: -0.16). The planner derives `offsetX` from the camera position `(80, 880, 280)`, perspective FOV 60°, and aspect 16:9 by solving the projection (researcher to provide the math). If the derivation is brittle for non-16:9 viewports, fall back to a viewport-aspect-aware computation in the renderer init.

### Case-star visibility during Entry (locked)
- **D-01.1-03:** All 116 case-star sprites are **hidden** during Entry (`star.visible = false` or material opacity 0). They are revealed via the existing `releaseStarsToHomes` tween inside `choreographPlanetaryToGlobal` — the tween already starts at `t = 0.2s × s` and runs 1.2s, which is the on-stage reveal moment. Reveal is implemented as a sprite opacity tween from 0 → 1 starting at `t = 0.4s` with duration 0.8s (overlaps the existing position tween so stars fade in *while* migrating to their orbital homes).
  - **Why not particle-texture the planet surface?** That's a Globe rebuild, not a scope-fix. Hiding aligns with the existing `isPlanetaryTarget` flag semantics — the flag already gates tick-loop control of these stars during Entry.
  - **Why not tune positions/scales?** Fragile — handoff's "field of free galactic particles inside" is an aesthetic that depends on the underlying sphere being a textured composite. We can't fake it with billboard sprites without it looking like the current bug.

### Camera-transition timing on ENTER_FIELD (locked)
- **D-01.1-04:** The Entry → State 1 camera transition runs as a **target re-aim** from `(offsetX, 0, 0)` → `(0, 0, 0)`, duration 1.2s, ease `power1.inOut` (matches `flyTo`). It is started from the same dispatch path that calls `choreographPlanetaryToGlobal` and runs in parallel with it. The choreographer sequence (planet fade, star release, label reveal) is unchanged; the camera target tween is an *additional* gsap tween fired alongside.
  - This means: at Entry → State 1 transition start, three things tween in parallel:
    1. Planet sphere fades out (existing, `choreographPlanetaryToGlobal` step 1+4)
    2. Stars migrate from sphere surface → orbital homes (existing, `releaseStarsToHomes`)
    3. Camera target moves off-center → centered (NEW in this phase)

### Files in scope (locked)
- **D-01.1-05:** Files modified by this phase:
  - `src/scene/renderer.ts` — set initial `controls.target = (offsetX, 0, 0)` if camera is in Entry state at boot. Or a new `setEntryFraming(controls)` helper.
  - `src/animation/transition-choreographer.ts` — extend `choreographPlanetaryToGlobal` to also tween `controls.target` from current → `(0,0,0)` during the 1.6s window.
  - `src/main.ts` — at boot, before `mountCalibrationOverture`, set Entry framing on the camera (target offset). Hide all `sceneObjects.starMeshes` (set `.visible = false`) until release tween fires.
  - `src/scene/planetary-gather.ts` — possibly extend `releaseStarsToHomes` to also tween sprite material opacity 0 → 1 during the position tween. Or add a sibling `revealStarsFromPlanet(objects)` helper.
  - **Tests:** new test files `src/scene/entry-framing.test.ts` (or extension to existing `planetary-gather.test.ts`) covering: camera target offset computation, star visibility lifecycle, choreographer camera-tween presence.

- **No changes to:** `src/ui/entry-screen.ts`, DOM overlay, CSS, ViewState event types, copy.

### Acceptance criteria (handoff parity is the gate)
- **D-01.1-06:** Phase is `passed` only when `01-UAT.md` Tests 8, 9, 10 all flip from FAILED/pending → passed. Specifically:
  - Test 8: Planet renders at viewport-relative cx ≈ 72% ± 4%, cy ≈ 58% ± 4%, apparent radius matches handoff within ±15% at 1280×800.
  - Test 9: Case-star sprites are not visible during Entry. Counted via `document.querySelectorAll('canvas').length` won't help — verification is via `sceneObjects.starMeshes.every(s => !s.visible)` evaluated through `browser_evaluate` or via Three.js scene introspection in a unit test.
  - Test 10: CTA click → 200ms editorial fade → 600ms State 1 reveal — and the camera target lands at (0,0,0) at the end of the choreographer timeline, not before. Stars are visible (opacity 1, not hidden) at end of choreography.

## Existing Code Insights

### Reusable Assets
- `flyTo()` in `transition-choreographer.ts` — gsap proxy pattern for camera tweens. Adapt for a target-only tween (no position change) by holding `px/py/pz` constant and only animating `tx/ty/tz`.
- `gatherStarsToPlanet()` already sets `userData.isPlanetaryTarget = true` per star. The new visibility gate can hook this flag — if the flag is set, sprite is hidden until release.
- `releaseStarsToHomes()` already iterates planetary-target stars during the choreographer. Extend the same iteration to tween opacity.

### Established Patterns
- Camera control: `camera-controls` library. `controls.setLookAt(px, py, pz, tx, ty, tz, false)` is the apply path. `controls.getTarget(new THREE.Vector3())` reads current target.
- gsap proxies for camera tweens — never tween THREE objects directly.
- Reduced-motion scaling: `s = prefersReduced ? 0.33 : 1.0`.

### Integration Points
- Boot sequence in `main.ts` runs: createRenderer → buildOrbitalScene → createPlanet → gatherStarsToPlanet → mountCalibrationOverture → mountEntryScreen. The camera framing for Entry must be set after `createRenderer` but before the first render tick. The star visibility=false must be set after `gatherStarsToPlanet` (or via the gather function itself) before the first render.
- The viewState subscriber that triggers `choreographPlanetaryToGlobal` already gates on `prev.kind === 'planetary' && next.kind === 'global'` — that's the trigger for `ENTER_FIELD`. The new camera-target tween fires from the same condition.

<specifics>
## Specific Ideas

- Compute `offsetX` from camera position `(80, 880, 280)` and FOV 60°. Camera looks roughly down at origin. To put origin at NDC (0.44, -0.16), the lookAt target shifts in world space such that origin appears off-center. The trigonometry: at distance ≈ √(80² + 880² + 280²) ≈ 925 from origin, with vertical FOV 60°, viewport half-height in world units at origin ≈ 925 × tan(30°) ≈ 534. NDC y = -0.16 means the target is offset upward in world space by 0.16 × 534 ≈ 85 units (so the planet appears below the optical center, which is what cy:58% means in screen space). Similar derivation for x: at aspect 16:9, half-width ≈ 950; NDC x = 0.44 → target offset leftward by 0.44 × 950 ≈ 418 units. **Researcher must verify and refine this math** — the camera doesn't look straight at origin (position is (80, 880, 280) not (0, h, 0)), so the offset has to be computed in the camera's local right/up vectors, not world axes.
- The choreographer's `setLookAt(...)` is the apply path; the camera-target tween must use it, not set `controls.target` directly (which `camera-controls` doesn't expose as a public setter on this library).
- For the visibility hide/reveal: `THREE.Mesh.visible = false` is cheap and the right primitive. Material opacity tween for the reveal feels softer than a binary visible flip and matches the editorial fade aesthetic.

</specifics>
