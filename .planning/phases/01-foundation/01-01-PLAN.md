- `interface EntryScreenOptions` with single field: `onEnter: () => void` (called after fade starts, 200ms)
- `function mountEntryScreen(parent: HTMLElement, options: EntryScreenOptions): void`

**DOM structure (innerHTML):**
```html
<div class="entry-screen">
  <div class="entry-hero">
    <p class="entry-eyebrow">— COSMO5 / OBSERVATORY / 2026.04</p>
    <h1 class="entry-headline">
      A cosmos of <em>proof</em>,<br>

    <p class="entry-body">
      One hundred and sixteen case studies, plotted as an atlas.<br>
      Navigate by gravity. Read by instrument.
    </p>
    <button class="entry-cta" type="button">
      <span class="entry-cta-dot">●</span>
      ENTER OBSERVATORY →
    </button>
  </div>
  <div class="entry-telemetry">
    116 cases · 13 markets · 7 verticals · 2014 — 2025
  </div>
</div>
```

**Implementation details:**
1. Create overlay div with `className: 'entry-screen'`
2. Set innerHTML to exact copy from D-05 in CONTEXT.md (includes eyebrow, headline with italic "proof", body, CTA button with pulsing dot, telemetry plate)
3. Append to parent (typically document.body)
4. Add event listener to `.entry-cta` button:
   - On click: add class `entry-screen--exiting` immediately (triggers CSS fade)
   - Wait 200ms (matches fade duration)
   - Call `options.onEnter()` callback
   - Remove overlay DOM element

**No framework, no GSAP for this overlay** — use CSS transition + class toggle (simpler for a one-time fade). GSAP will be wired at the main.ts integration level for the State 1 fade-in (600ms).

**Pattern reference:** Follow src/ui/calibration-overture.ts DOM mount/unmount approach exactly.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input (CTA click) | DOM event from user; no untrusted data |
| Callback invocation | onEnter callback supplied by caller (main.ts); will dispatch to ViewStateMachine |
| DOM injection | Entry screen HTML is static, handoff-defined copy; no dynamic injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | **S** Spoofing | CTA button | accept | Button type="button" prevents form submission hijacking; click handler is local |
| T-01-02 | **I** Information Disclosure | Entry copy display | accept | No user data displayed; only static handoff copy |
| T-01-03 | **D** Denial of Service | Rapid CTA clicks | accept | onEnter callback fires once per click (no debounce needed per design); DOM removal happens on first fire so subsequent clicks have no effect |

All threats are low-risk (static content, no network, no data). No mitigations required beyond existing DOM safety practices.
</threat_model>
